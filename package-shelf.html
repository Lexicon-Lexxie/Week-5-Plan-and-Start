ESSENTIAL CONCEPT The File System

Looking Inside the Workshop

When you inspect a modern JavaScript or TypeScript project, these key files work together to manage external code cleanly:

01 · package.json is the parts list

It names your project and lists the external packages it depends on. Because it is a small, lightweight text file, it easily lives in version control (Git).

02 · npm fetches the tools

Running npm install reads your package.json, contacts the online registry, and downloads local copies into your local workspace.

03 · node_modules stays off GitHub

The downloaded code is stored in a folder called node_modules. It can contain thousands of files and megabytes of code. We put node_modules in our .gitignore file so our Git repository remains clean and fast. Anyone who clones the project can recreate the folder in seconds by typing npm install.

04 · Your code imports what it needs

Once installed, your JavaScript files can import specific functions using import or require statements, giving you instant superpowers without writing thousands of lines of boilerplate.

TERMINOLOGY Definitions

Template vs. Library vs. Package

Newcomers often hear these three terms interchangeably. Here is how professional software engineers distinguish them:

Starter Foundation

Template

A pre-arranged starting structure that you copy and customize. It gives you boilerplate folders, build settings, and layout, but becomes your own code once you edit it.

Specific Capability

Library

A focused collection of helper functions and classes (for example, Three.js for 3D graphics or Lodash for data utilities) that you call when you need them.

Distributable Bundle

Package

A standardized unit of software published to a registry with a name, version number, and manifest (package.json) so other developers can easily install it.
